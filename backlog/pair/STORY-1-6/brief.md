## Acceptance criteria (verbatim)
1. Given a completed pipeline run matching ARCH-2's trigger point, when the hook fires, then a valid `schema: 1` JSON file exists under `<project>/.agentic-sdlc/runs/` within that session.
2. Given `node` is missing or any input the hook needs is absent, when the hook fires, then it exits `0` and writes nothing, exactly like `meter.sh`'s degrade path — the session is never failed by this hook.
3. Given a run that spans multiple sessions (ARCH-4: same command and target as the existing marker), when the second session's hook fires, then the SAME `.agentic-sdlc/runs/<run_id>.json` is rebuilt in place with `run.sessions` incremented and wall clock accumulated — one run, one file, no duplicate report; and a different command/target instead finalizes the old run and starts a new `run_id`.
4. Given `.agentic-sdlc/runs/` is new, when the hook writes to it, then the directory is gitignored, matching `.agentic-sdlc/meter/`'s existing treatment.

## Binding decisions (ARCH-2, ARCH-4 — resolved, do not re-decide)

Also register it in THIS repo's `.claude/settings.json` hooks block the same way meter.sh is registered there (with `RUN_REPORT_MJS="$CLAUDE_PROJECT_DIR/plugins/agentic-sdlc/scripts/run-report.mjs"`). - Mirror `templates/hooks/meter.sh`: best-effort, advisory, ALWAYS exit 0; `node` missing → exit 0; resolve run-report.mjs via `RUN_REPORT_MJS` override, then install cache highest version (`~/.claude/plugins/cache/*/agentic-sdlc/<ver>/scripts/run-report.mjs`, version-sorted), then marketplace clone; `$CLAUDE_CONFIG_DIR` replaces ~/.claude when set. - KNOWN TRAP: macOS ships bash 3.2. With `set -u`, expanding an empty array `"${arr[@]}"` aborts ("unbound variable") — meter.sh has exactly this bug (logged debt). Use `${arr[@]+"${arr[@]}"}` or avoid arrays. Tests must pass under /bin/bash 3.2 on macOS.
- UserPromptSubmit branch: fires on EVERY prompt, so do a cheap prefix check FIRST: the payload's `prompt` starts with `/agentic-sdlc:plan`, `/agentic-sdlc:build` or `/agentic-sdlc:review` (else exit 0 immediately). NEVER write anything to stdout (it is injected into the model's context) — redirect everything. Then write/rotate `<project>/.agentic-sdlc/run-state.json` (project = payload `cwd`, fallback $CLAUDE_PROJECT_DIR): fresh uuid v4 run_id, command, lane (`--fast` present → fast, else deliberate), target (raw arg minus `--fast`), started_at (now, ISO UTC), sessions, wall_clock_s_prior, arch_snapshot (ARCH-<n> IDs in the resolved backlog file at run start; [] if none yet), debt_snapshot (count of `###` entries under docs/TOOLING-DEBT.md's "## Logged by agents" block; null if no ledger), backlog (resolved path or null). The marker shape is already fixed and documented in the header of plugins/agentic-sdlc/scripts/run-report.mjs ("THE RUN MARKER") — conform to it. Marker writing logic is best placed as a new subcommand of run-report.mjs (e.g. `run-report.mjs mark --project <dir> --prompt-file <f> --session <id>`) so it's testable in Node; keep the shell thin.
  - Same command AND same target as the existing marker → CONTINUE the run: keep run_id; if the payload `session_id` differs from the marker's last session → sessions+1, fold the previous session's elapsed time into wall_clock_s_prior, started_at = now. Same session re-prompting the same command → no sessions bump.
  - Different command or target while a marker exists → first build the superseded run's report (final rebuild, synchronous is fine here but bounded), then write the new marker with a fresh run_id.
  - Wall clock MUST NOT double count across SessionEnd folds, supersession rebuilds and continuations. You may add local-only fields to the marker (e.g. `session_id`, `session_open`) if run-report.mjs's marker parser tolerates/understands them — minimal, documented edits to run-report.mjs's marker handling are in scope; update its header doc. Run-report schema 1 (the REPORT) must not change.
- SessionEnd branch: hard 1.5-second budget shared by all SessionEnd hooks, cannot block. Spawn `node run-report.mjs report --project <dir>` DETACHED (`nohup … >/dev/null 2>&1 &`, setsid if available) and exit 0 at once. No marker on disk → exit 0, write nothing. The report overwrites `.agentic-sdlc/runs/<run_id>.json` (ARCH-4: one run = one file, full rebuild every time).
- AC4: `.gitignore` already excludes `.agentic-sdlc/` in this repo; for consuming projects, `docs/setup.md` and/or the templates must state that `.agentic-sdlc/` (meter/, runs/, run-state.json) is gitignored — find where meter's ignore rule is documented and extend it.
